接单前必问清单（软件定制 · 7 类）
════════════════════════════════════
用法：报价前照着问一遍，问不全就先不报价。
标注"⚠"的是最常见的返工点，务必问到具体答案，别接受"差不多""应该可以"。

────────────────────────────────────
一、通用五问（任何单都先问）
────────────────────────────────────

1. 跑在哪
   什么系统、什么版本、谁的机器（个人电脑 / 公司电脑 / 服务器）、有没有外网。

2. 谁在用
   几个人用、一天用几次、是固定流程还是临时用一次。

3. 输入是什么
   要一个真实样例：文件、截图、网址都行。同时问清一次多少量（几十条还是几万条）。

4. 输出要什么
   文件、界面、还是接口？给个参考样子最好（现有表格、别人的软件截图）。

5. 怎么算验收、什么时候要
   谁点头算通过、有没有硬性截止时间。

────────────────────────────────────
二、分类清单
────────────────────────────────────

【1】桌面软件（Windows / macOS）

· 系统版本：Windows 10 / 11？还要兼容 Win7 吗？macOS 要不要一起做（Intel 还是 Apple 芯片）
· 安装条件：要不要管理员权限？公司电脑有没有装杀毒、域控、禁止装软件
· 界面要求：要不要界面？有没有参考样式？单机用还是多台机器共用数据
· 数据存哪：本地文件、本地数据库、还是要连服务器
· 交付形态：安装包还是绿色免安装；要不要代码签名（不签名会被系统拦）
⚠ 返工点：Win7 兼容、杀毒误报 exe、高分屏和字体错位
⚠ 我这边无法真机验证 Windows 界面和打包，必须你在 Windows 上跑一遍再交付

【2】Linux 发行版软件

· 发行版和版本：Ubuntu 20 / 22 / 24、CentOS 7、Debian 11 / 12、Arch，具体到版本号
· CPU 架构：x86_64 还是 ARM
· 运行方式：命令行、systemd 常驻服务、还是 Docker
· 安装环境：能不能联网装依赖？内网离线的话要提前说
· 权限与安全：是不是 root 跑，有没有 SELinux、防火墙、堡垒机限制
⚠ 返工点：CentOS 7 的 glibc 太老，新版 Python / Node 装不上；内网拉不到依赖
⚠ 交付前必须确认目标机器能跑，最好给一条自检命令

【3】脚本与自动化

· 触发方式：手动双击，还是定时（几点、多久一次）
· 跑在哪：客户自己的电脑、你的服务器、还是云主机；电脑会不会关机、锁屏
· 输入：文件从哪来、什么格式、一次多少条
· 异常处理：报错是跳过继续还是中断？要不要日志、要不要通知（邮件 / 微信 / 钉钉）
· 依赖：客户机器上能不能装 Python / Node，还是必须打包成单文件
⚠ 返工点：客户电脑没环境、文件正在被 Excel 占用、路径带中文和空格
⚠ 一定要问"电脑关机的时候要不要跑"，这决定是脚本还是服务

【4】数据工具（采集 / 清洗 / 报表）

· 数据来源：公开网页、公开接口，还是内部系统？需要登录的一律先确认合规性
· 字段清单：要哪几列，每列什么含义、什么格式，最好给个目标表格
· 频率与量级：一天几次、一次多少条、跑多久能接受
· 反爬情况：有没有验证码、频率限制、封 IP；能不能接受慢速采集
· 输出去向：Excel、CSV、数据库，还是直接进报表；去重和清洗规则是什么
· 用途：数据拿去干什么，会不会涉及个人信息
⚠ 返工点：字段定义含糊（"差不多这些"）、网站改版、验证码挡路
⚠ 需要账号登录、涉及他人隐私数据的，直接不接

【5】插件开发

· 宿主平台：Excel 2016 / 365 / WPS？Chrome / Edge / 360 浏览器？版本要说清
· 安装条件：客户能不能自己装，公司有没有禁用加载项
· 权限范围：插件要读哪些数据、要不要联网、要不要访问本地文件
· 交互形态：按钮、任务窗格、右键菜单，还是自动触发
· 分发方式：自己发给客户，还是上架商店（上架需要审核和开发者账号）
⚠ 返工点：Office 和 WPS 双兼容、企业策略禁止加载插件
⚠ 我这边只能验证浏览器插件，Office 插件要你在客户机器上装完实测

【6】接口对接

· 有没有文档：接口文档、字段说明、错误码，先要一份
· 有没有测试环境：测试地址、测试账号、key / token，缺一样都难保证联调
· 认证方式：Token、OAuth、签名、白名单 IP
· 频率限制：QPS 上限、每天调用量
· 数据方向：单向还是双向，实时还是定时同步
· 出问题找谁：对方有没有技术支持联系人
⚠ 返工点：只有文档没有测试环境、对方接口不稳定、字段对不上
⚠ 明确写进聊天：只在测试环境联调通过，生产环境问题不含在内

【7】二次开发

· 有没有源码：什么语言、能不能编译跑起来、依赖能不能装
· 授权与文档：原来的开发者是否同意改，有没有设计文档
· 改动范围：加功能、改逻辑，还是修 bug；哪些地方不能动
· 原厂升级：以后原软件升级，改动怎么办
· 交付方式：在原工程上改，还是单独出一份
⚠ 返工点：只给成品不给源码、老项目依赖装不上、授权不清
⚠ 没有源码只有安装包的，先说明"只能做外围工具，改不了内部逻辑"

────────────────────────────────────
三、报价前必须落在聊天里的 5 行
────────────────────────────────────
1. 做什么：功能逐条列，一条一行
2. 不做什么：边界写清楚（比如"不含界面美化""不含服务器部署"）
3. 交付什么：安装包 / 脚本 / 说明文档，具体到文件名
4. 工期与节点：什么时候给第一版演示，什么时候能验收
5. 修改与售后：范围内免费改几次，之后怎么算，售后多久

有这 5 行，后面 90% 的扯皮都能避免。

────────────────────────────────────
四、可直接复制给客户的问询模板
────────────────────────────────────
「为了给你准确报价，麻烦回我 5 条：
1）跑在什么系统 / 什么软件上，版本是多少
2）现在这件事你是怎么做的（截图或录屏最好）
3）给我一个输入样例
4）最后要得到什么结果（表格、界面截图都行）
5）什么时候要用
如果有对接的系统，再加一条：有没有接口文档和测试环境。
这 5 条齐了，我当天给你报价和工期。」

────────────────────────────────────
五、判断要不要接（三条红线）
────────────────────────────────────
· 要客户生产系统权限、要登录别人账号的 —— 不接
· 需求只有一句话、给不出任何样例的 —— 先不报价，让对方补材料
· 报价压到明显做不完的 —— 不接，做一半烂尾比不接更亏
